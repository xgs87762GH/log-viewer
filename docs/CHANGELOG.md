## v1.0.3

- 下载文件按「中文环境标签_项目展示名_级别.log」命名（如「测试环境_订单服务_INFO.log」，环境取配置 `label`、缺失回退 key；`utils/downloadName.js`），前端保存名与后端附件头保持一致。
- 新增配置导入导出：设置页第四分区、归档纯函数与编排层、后端 `GET /api/config/export` / `POST /api/config/import`（白名单、1MB 上限、结构校验、备份与原子写）；导入前预览并逐项勾选。
- 仪表盘级别按钮显示当前日志文件大小：目录列表 HTML 自带大小，解析后随索引持久化，探测级别或按日软刷新后自动出现，不增加额外请求。
- 版本更新提示：页面加载时比对 GitHub 最新 tag 与本地版本（`utils/versionCheck.js` 语义化比较 + 1 小时缓存），更高版本时在侧栏版本号旁显示可点击的「有更新」标签；网络不可达 / 限流 / 非法 tag 静默降级。端点与链接集中在 `constants/versionCheck.js`，缓存键纳入 `storageKeys.js`。
- 导入配置即生效：本地段写入后立即触发各 composable 的 `reload()`，设置页订阅 `useSettings` 的提交广播同步草稿，导入后不再提示「有未保存的更改」，也不再需要刷新页面。
- 仪表盘卡片修复：服务名过长时 IP 不再被挤压或截断——应用名改为只收缩不撑开（截断后 IP 紧随其后，消除右侧大段空白），移除主机名的 62% 宽度上限，长主机名在紧凑布局下也完整可见。
- 代码规范收敛：本地存储键统一到 `constants/storageKeys.js`；配置段升级为 `configBundle.js` 的 `SECTION_DEFS` 唯一 descriptor（新增段只改一处）；设置分区按常量动态挂载；消除重复写设置、模块级正则状态与前后端附件名清洗规则不一致。
- 验证：构建、**89/89** 单测、4 个 Python 文件 `py_compile`、lint 0、59 个文档相对链接、无头浏览器核对（导入即生效端到端、双主题、仪表盘长服务名下 IP 完整可见）均通过。

## 已知限制

- 日志正文**不落盘**，只在浏览器内存保留 60 秒、最多 12 份；刷新页面即丢失。
- `ETag` / `Last-Modified` 只记入缓存 meta，代理未转发上游这两个头，条件请求尚未启用。
- 上下文弹窗只读已加载的尾部数据，更早的行不联网补拉；按字节区间拉取列为后续方向。
- 整文件下载的 Range 分片 / 断点续传为预留设计，尚未实现。
- 日志正文无轮询；统计页与在线心跳有自己的定时器。
- 三套主题下日志正文区保持独立深色色板（设计选择）。

## 后续方向

- 打通条件请求（`ETag` / 304）与缓存 meta，减少重复传输。
- 上下文按需按字节区间补拉，解除「只有尾部」的边界。
- 后端传输升级；正文是否允许持久化需先确认再评估。
- 继续收敛大日志下的过滤与渲染耗时。
